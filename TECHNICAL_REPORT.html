1. Tổng Quan Dự Án & Bối Cảnh Thực Tế

Ứng dụng VKU Room Booking được phát triển nhằm giải quyết nhu cầu mượn và quản lý không gian học tập, phòng lab thực hành tại trường Đại học VKU bao gồm các khu giảng đường trọng điểm: Khu V (Phòng thực hành chuyên sâu AI, Mạng & Phần mềm), Khu A (Phòng hội thảo thông minh và hội trường lớn), Khu K (Không gian sáng tạo Maker Space, Robotics & Bán dẫn) và Thư viện số.

Dự án hiện thực hóa trọn vẹn 100% mục tiêu kỹ thuật trong bài giảng Tuần 6 — React Native (Part 2): Navigation, State Management & Animations:

  • Kiến trúc điều hướng Type-Safe lồng ghép Native Stack và Bottom Tabs (React Navigation).
  • Quản lý trạng thái phân tầng: Client State với Zustand (AsyncStorage persist) và Server State với TanStack Query.
  • Hiệu ứng chuyển động mượt mà 60fps trên UI thread với React Native Reanimated 3.
  • Xử lý cử chỉ vuốt gốc với React Native Gesture Handler (Swipe to Cancel).

2. Thiết Kế Kiến Trúc Điều Hướng (Navigation Architecture)

Ứng dụng sử dụng mô hình Nesting Navigators (Slide 4, 7, 8, 9), trong đó BottomTabNavigator được lồng bên trong RootStackNavigator. 

Root NavigationContainer
└── Stack.Navigator (RootStack) [headerStyle: #1E3A5F, headerTintColor: #fff]
    ├── Screen "MainTabs" ──► Tab.Navigator [activeColor: #3B82F6]
    │   ├── "BrowseRooms" ──► BrowseRoomsScreen (Khám phá)
    │   ├── "MyBookings"  ──► MyBookingsScreen (Lịch đặt phòng)
    │   └── "Profile"     ──► ProfileScreen (Hồ sơ sinh viên)
    ├── Screen "RoomDetails" (Pushed on top — tabs hidden, params: { roomId, roomName })
    └── Screen "BookingConfirmation" (Modal Presentation — trượt từ đáy màn hình)

Đảm bảo an toàn kiểu dữ liệu (Type-Safe Route Parameters - Slide 6)

export type RootStackParamList = {
  MainTabs: NavigatorScreenParams<TabParamList> | undefined;
  RoomDetails: { roomId: string; roomName: string };
  BookingConfirmation: { bookingId: string };
};

export type TabParamList = {
  BrowseRooms: undefined;
  MyBookings: undefined;
  Profile: undefined;
};

Nhờ việc định nghĩa các tham số kiểu chặt chẽ, việc điều hướng được bảo vệ trước lỗi thời gian chạy (runtime crash), đồng thời hỗ trợ kiểm tra tĩnh toàn diện qua tsc --noEmit.

3. Quản Lý Trạng Thái Phân Tầng: Zustand & TanStack Query

Theo phân tích tại Slide 11 và 15, việc tách biệt Client State và Server State mang lại hiệu năng cao và cấu trúc mã nguồn sáng sủa:

Tiêu chí Zustand (Client State) TanStack Query (Server State)
Bản chất dữ liệu Danh sách đặt phòng của người dùng, tùy chọn giao diện Danh sách phòng, thiết bị, tình trạng từ máy chủ VKU
Cơ chế lưu trữ / Caching Lưu ngoại tuyến qua middleware persist + AsyncStorage Tự động lưu bộ nhớ đệm (Cache) theo staleTime và gcTime
Tối ưu Re-render Trích xuất dữ liệu qua Atomic Selectors Chỉ re-render khi trạng thái truy vấn (query) thay đổi

3.1. Zustand Persistent Store (Slide 12 & 13)

export const useBookingStore = create<BookingState>()(
  persist(
    (set) => ({
      bookings: [...initialDemoBookings],
      addBooking: (b) => set((s) => ({ bookings: [b, ...s.bookings] })),
      cancelBooking: (id) =>
        set((s) => ({
          bookings: s.bookings.map((b) =>
            b.id === id ? { ...b, status: 'cancelled' } : b
          ),
        })),
    }),
    {
      name: 'vku-booking-storage',
      storage: createJSONStorage(() => AsyncStorage),
    }
  )
);

Tại màn hình MyBookingsScreen, việc sử dụng useBookingStore((s) => s.bookings) và useBookingStore((s) => s.cancelBooking) đảm bảo chỉ các thuộc tính cần thiết được lắng nghe, triệt tiêu re-render toàn diện.

3.2. TanStack Query Custom Hook (Slide 16, 17, 18)

export function useRooms(building?: string) {
  return useQuery<Room[]>({
    queryKey: ['rooms', { building }],
    queryFn: async () => fetchRoomsApi(building),
    staleTime: 5 * 60 * 1000, // Dữ liệu tươi trong 5 phút
    gcTime: 10 * 60 * 1000,    // Thu dọn sau 10 phút
    retry: 2,
  });
}

Danh sách phòng được kết nối với thao tác Pull-to-refresh của FlatList thông qua refreshing={isLoading} và onRefresh={refetch}.

4. Tối Ưu Trải Nghiệm Người Dùng (Reanimated 3 & Gesture Handler)

4.1. Layout Animations & Spring Interactions (Slide 21, 22, 23)

Khác với Animated chạy trên luồng JavaScript, Reanimated 3 chạy trên UI thread thông qua Worklets:

  • Staggered Card Entry: Thẻ phòng RoomCard xuất hiện nối tiếp với FadeInDown.delay(index * 80).springify() và bố cục tự sắp xếp Layout.springify().
  • Nút bấm đàn hồi (BookButton): Sử dụng useSharedValue(1), onPressIn nảy về 0.95, onPressOut nảy về 1.0 tạo cảm giác xúc giác chân thực.

4.2. Native Gesture Handling (Slide 25 & 26)

const pan = Gesture.Pan()
  .activeOffsetX([-10, 10])
  .onUpdate((e) => {
    translateX.value = Math.min(0, e.translationX);
  })
  .onEnd((e) => {
    if (e.translationX < -120) {
      runOnJS(onCancel)(bookingId); // Kích hoạt hủy phòng trên JS thread
    }
    translateX.value = withSpring(0);
  });

Cử chỉ vuốt sang trái làm lộ biểu tượng thùng rác màu đỏ với hiệu ứng trượt 60fps, loại bỏ độ trễ và sự xung đột với cuộn danh sách của hệ điều hành.
